# Prompt 私人工作台

[![Deploy to Cloudflare](https://deploy.workers.cloudflare.com/button)](https://deploy.workers.cloudflare.com/?url=https://github.com/0511150/prompt-manager)

点击按钮，将应用部署到你自己的 Cloudflare 账号；需要先开通 R2。在部署页面的 Secret 字段 `ACCESS_PASSWORD` 中直接设置网站访问密码（12–512 字符）。部署完成后打开网站，用刚设置的密码登录。无需初始化码，也无需在网站上再次设置密码。

一键部署读取 `wrangler.jsonc`，默认部署命令为 `npm run deploy`；资源由 Cloudflare 创建和绑定。`ACCESS_PASSWORD` 作为 Cloudflare Secret 保存；应用自动生成 PBKDF2-SHA-256 加盐校验结果、会话密钥和数据加密密钥，并持久化到 `AccessControl`。网站不提供公开的密码设置或重置接口。

基于 Cloudflare Workers、R2 和 Durable Objects 的单用户 Prompt 管理器。

## 功能

- 嵌套文件夹、独立的收藏文件夹，以及不设数量上限的顶部文档标签；标签过多时可横向滚动，打开文档时自动显示当前标签。点击“我的 PROMPT”进入根目录，点击文件夹在右侧浏览内容。
- 拖动 Prompt 调整同一目录内的顺序，或移动到其他文件夹；顺序自动保存，可随工作区历史和本地备份恢复。排序独立于正文编辑锁。
- 直接编辑 Markdown，支持预览、左右对照及 LaTeX 公式；公式嵌入正文显示，不单独居中另起一行。
- 模板变量区默认收起，点击标题展开。使用 `@@变量名@@` 编写模板；预览自动替换变量，“复制成品”复制完整结果。
- 保存常用变量组合并一键填入：同一 Prompt 文件夹共享组合库，不同文件夹、子文件夹及根目录 Prompt 各自独立。
- Prompt、收藏和文件夹使用紧凑右键菜单；表单、设置和历史记录使用无全屏遮罩的小浮层。
- 每份 Prompt 独立取得服务器编辑权，其他位置只读，其他文件仍可同时编辑。
- 空闲后自动保存并解锁，设置中可按秒调整，默认 10 秒；离线自动保留本地草稿，联网后核对版本再同步。
- 统一访问密码、12 小时登录会话、退出撤销、持久化 IP 失败封禁。
- R2 加密保存当前工作区和默认 20 条旧状态（设置中可调整为 1–1000 条），可在设置中预览、恢复。
- 备份下载到本机，导入从本机选择文件。

只有一个私人工作区，没有注册或多空间入口。格式语法直接手写，不提供格式插入工具栏。

## 本机开发

需要 Node.js 22.18 以上和 npm。Cloudflare CLI、Wrangler 和 Miniflare 已包含在开发依赖中。

```sh
npm ci
npm run setup:dev
npm run dev
```

打开 `http://127.0.0.1:8787/`。本机测试密码是 `local-integration-password-only`，只适用于本机测试。

`setup:dev` 仅在 `.dev.vars` 不存在时生成测试凭据，已有文件不会被覆盖。不要将真实生产密钥放进本机测试配置。

保持开发服务运行，在另一个终端执行：

```sh
npm test
npm audit --omit=dev
```

集成测试连接本机 Workers 运行时及模拟存储，不得对生产工作区运行。GitHub Actions 自动执行同样的构建、依赖检查和测试。

## 部署到 Cloudflare

一键部署和新部署使用 `wrangler.jsonc`（不含个人账号或域名）。部署界面会要求 Secret `ACCESS_PASSWORD`，此处填写的就是之后的网站登录密码。手动部署可使用 `npx wrangler secret put ACCESS_PASSWORD` 输入密码后，再执行 `npm run deploy`。

现有基于 cf 的部署仍使用 `cloudflare.config.ts`，其更新命令为 `npm run deploy:cf`。继续更新旧部署前先登录：

```sh
npx cf auth login
```

部署参数通过环境变量提供，仓库不包含个人账号或域名：

| 环境变量 | 用途 | 默认值 |
| --- | --- | --- |
| `CLOUDFLARE_ACCOUNT_ID` | 目标 Cloudflare 账号 | 由 CLI 的登录账号选择 |
| `CLOUDFLARE_WORKER_NAME` | Worker 名称 | `prompt-manager` |
| `CLOUDFLARE_R2_BUCKET` | R2 桶名称 | `prompt-manager-vaults` |
| `CLOUDFLARE_CUSTOM_DOMAIN` | 可选自定义域名，所属区域须位于目标账号 | 不绑定，使用 workers.dev |

PowerShell 示例（把占位符换成自己的值）：

```powershell
$env:CLOUDFLARE_ACCOUNT_ID='YOUR_ACCOUNT_ID'
$env:CLOUDFLARE_CUSTOM_DOMAIN='prompt.example.com'
npm run build
npx cf deploy --dry-run
```

以下配置仅用于兼容旧版部署；一键部署的新用户无需手动生成这三个 Secret：

| Secret | 内容 |
| --- | --- |
| `ACCESS_PASSWORD_HASH` | 高熵访问口令的 SHA-256 十六进制摘要 |
| `SESSION_SECRET` | 至少 32 字节安全随机数据生成的会话签名密钥 |
| `DATA_KEY` | 32 字节安全随机 AES 密钥的 Base64 编码 |

维护旧版部署时，可在本机创建被 Git 忽略的 `.env.production.secrets` 文件，填入上述三个 Secret（`名称=值`，一行一个），再执行：

```sh
npm run build
npx cf deploy --secrets-file .env.production.secrets
```

R2 桶与 Durable Object 由 CLI 按配置创建或绑定；账号需要开通 R2。旧部署常规更新使用 `npm run deploy:cf`，会先重新构建前端。新部署使用 `npm run deploy`，由 Wrangler 的构建步骤生成资源。直接调用 `cf deploy` 时，应先运行 `npm run build`。

**更新现有部署时，请继续使用原账号、Worker、R2 桶和自定义域名配置。不要替换 `DATA_KEY`。** 首次部署完成后，密钥应另行安全保管；不要加入 GitHub、Issue 或构建日志。

## 访问保护

- 未登录时，工作台页面、脚本、字体和数据接口由服务端阻止访问，仅公开登录所需资源。
- Cookie 使用 Secure、HttpOnly、SameSite=Strict；会话最长有效期为 12 小时。
- 15 分钟内输错 5 次，临时封禁来源 IP 15 分钟，每次时长固定。滚动 24 小时内第 5 次触发封禁，转为永久封禁。永久封禁需管理员从其他 IP 或白名单 IP 登录后手动解除。成功登录清空该 IP 的全部失败与封禁统计。
- 使用 Cloudflare 提供的 `CF-Connecting-IP`，不信任客户端转发的 `X-Forwarded-For`。
- 修改密码摘要会使现有会话失效；退出立即撤销当前会话。
- 服务器逐文件编辑租约与版本检查阻止同一文件互相覆盖；不同文件的修改合并保存，R2 最终写入仍使用 ETag 条件保护。旧页面和历史恢复同样遵守当前文件的编辑权。

在「设置 → 登录保护 · Fail2ban」可查看失败次数、最近 24 小时触发次数、临时/永久封禁状态，手动解除并清空记录，以及添加/移除白名单。白名单支持单个 IPv4 和 IPv6 地址，不支持通配符或网段；白名单仍须正确密码。添加白名单时会清空该 IP 的已有统计。

新部署的访问密码作为 Cloudflare Secret 保存；密码校验、会话密钥、数据密钥与封禁/白名单保存在 SQLite Durable Object 中，不占用 R2 历史。不要删除 `AccessControl` 数据或绑定，避免丢失访问凭据与解密密钥。旧部署继续使用已有凭据，升级不会重置密码或更换密钥。在 Cloudflare 更新 `ACCESS_PASSWORD` 后重新部署，应用会更新密码校验并使旧登录失效，同时保留原有数据密钥、R2 内容和可解密的备份。

详见 [安全说明](SECURITY.md)。服务器可解密工作区数据，本项目不提供端到端加密。

## 变量组合的共享范围

上方输入框是当前 Prompt 正在使用的值；「保存组合」会将这些值另存为一张资料卡。之后修改输入框不会自动改写资料卡，也不会改动其他 Prompt 的输入值。点击组合的「填入」后，才会将保存的值套用到当前 Prompt。

组合库以左侧 Prompt 所在的文件夹划分，同一层文件夹中的 Prompt 共用已保存组合；父文件夹、子文件夹及其他文件夹各自独立。根目录的每份 Prompt 使用自己的私人组合库。顶部收藏文件夹不影响组合归属。

根目录 Prompt 放入文件夹后，原有私人组合会归入目标文件夹并共享。移动到其他文件夹时使用目标文件夹的组合库；移回根目录时，在组合数量上限内保留独立副本，后续修改不影响原文件夹。删除文件夹时，其组合移至上级；内容移至根目录时保留独立副本，数量限制导致无法复制的组合保留为待归类。

升级前没有归属信息的旧组合，仅在保存值能唯一对应一个范围时自动归类；其余内容保留在「组合库 → 旧组合待归类」，由你选择归入当前范围后使用。不会将无法确定归属的旧组合继续共享到全部文件夹。加密备份、导入和修改记录均保留组合的归属。

## 编辑权与离线草稿

点击正文、标题和变量输入框，取得该 Prompt 的独立编辑权。正文、名称、变量值、移动和删除都受到保护。其他页面可浏览、复制和预览，但不能修改同一文件；编辑不同文件互不占用编辑权。

每个文件按自己的最后修改时间计时，默认空闲 10 秒后自动保存并解锁。打开「设置 → 空闲锁定时间」可输入 1–86400 的整数，单位为 s（秒）。设置保存到工作区并在其他页面下次同步时应用；调整时间会按各文件最后一次修改的时间重新计算，不改变文件的编辑权。编辑计时设置不占用 R2 修改记录。「保存并解锁」和 Ctrl/⌘ S 可提前保存。切到后台会尝试保存。服务器只在保存成功后释放对应文件。编辑权每 30 秒续期，有效期为 150 秒；页面关闭、断线或浏览器暂停后无法续期，会自动过期。保存请求携带页面、登录会话、编辑令牌及文件原版本，旧令牌不能覆盖新编辑。

本地草稿使用 IndexedDB 持续保存到当前浏览器，不写入 R2。断网期间可继续修改，联网后重新取得编辑权并检查原版本；若云端已更新，保留本地草稿并提供「保留为新 Prompt」或「使用云端内容」。重新打开页面后，可从文档或「设置 → 本地草稿」查看、恢复草稿。标签页和文件夹展开状态保存在当前浏览器，不消耗云端历史次数。

草稿属于当前浏览器配置文件，不能替代本地备份；清除网站数据或使用不保留数据的隐私模式可能使草稿丢失。离线时下载的手动备份为普通 JSON（未加密）；联网时仍下载由服务器加密的备份。导入和历史恢复若涉及正在编辑的文件，会被阻止，避免覆盖未保存的修改。

编辑租约存在 WorkspaceEditor 的 SQLite 表中，以文件 ID 独立记录；同一工作区的 R2 快照提交短暂串行合并，不把整个工作区锁成只读。历史仍是完整工作区快照，默认保留 20 条。

## 备份和历史

当前状态在 `workspace/current.json`；按设置保留旧状态（默认 20 条，最多 1000 条）在 `workspace/history/`，均为加密内容。历史目录包含时间、操作类型和数量等元数据。标签切换、文件夹展开和仅更新时间变化不会消耗历史次数。

设置中的恢复会保存恢复前的状态。超过上限自动清理最旧记录；后台按小时清理写入中断遗留的临时历史候选。软件源码、构建产物和发布包不写入 R2。

手动备份通过浏览器下载到本机，使用 `DATA_KEY` 加密，只能由使用同一密钥的工作区恢复。保管好该密钥；更改访问密码无需更换数据密钥。

支持导入当前格式备份、普通 JSON 和旧版多空间加密备份。导入旧版加密文件时在本机输入其旧主密码。旧版多空间 API 不再提供。

## 源码结构

- `src/app.js`：前端交互、预览与同步。
- `src/model.js`：数据模型、验证和模板变量。
- `src/preset-scopes.js`：组合库范围、移动处理与旧组合归类。
- `src/private-worker.mjs`：门禁、工作区、备份和历史 API。
- `src/access-control.mjs`：部署密码、持久化凭据、IP 封禁与白名单。
- `src/auth-guard.mjs`、`src/ban-policy.mjs`：会话撤销与封禁规则。
- `src/workspace-store.mjs`：当前状态、可调历史记录与并发条件写入。
- `src/workspace-editor.mjs`：逐文件租约、版本验证和 R2 合并提交。
- `src/editing-client.js`、`src/edit-protocol.js`：空闲保存、续期、冲突保护与共享比较规则。
- `src/local-drafts.js`：浏览器本地草稿存储。
- `src/server-crypto.mjs`：会话签名和 AES-GCM 加密。
- `public/`：页面、登录和样式。
- `tests/`：变量、加密、访问控制、IP 封禁、备份及历史恢复测试。

`dist/`、`src/assets.generated.mjs`、本机配置、凭据和测试存储均不应提交。构建时会重新生成前端资源；请不要把个人工作区备份放进仓库。

## 图片附件

- 支持粘贴截图、拖入图片和选择本机文件；PNG、JPEG、WebP，单张最多 8 MB、3200 万像素。
- 图片按原始文件内容的 SHA-256 保存为加密 R2 对象 `workspace/images/<hash>.bin`。多个文档引用同一哈希时不重复保存原图。文档保存文件名和 Markdown 引用。
- 「复制文字」将站内图片地址转换为明确的图片名称，并附上图片清单；「复制图片」打开大图列表，可逐张复制、下载原图或下载全部 ZIP。
- ZIP 完全在浏览器生成，使用 ZIP STORE，仅打包不压缩，保留原始文件名。普通网页不能一次可靠复制多个独立图片项目，因此不提供会漏图的假多图复制。
- 已保存状态及保留历史均无引用的图片进入 7 天找回期，在「设置 → 图片回收站」可插入当前 Prompt。仍被保留历史引用的图片受保护；定时任务每小时清理逾期图片。
- 有图片时，完整备份导出为 ZIP，内含工作区与图片。联网备份内容加密；离线备份未加密，需妥善保存。旧版 JSON 仍可导入。ZIP 与手动备份只下载到本地，不存入 R2。
- 编辑中的新图片先保存在本机 IndexedDB；联网保存文档前上传。预览使用已登录接口或本机缓存，不公开 R2 桶。
